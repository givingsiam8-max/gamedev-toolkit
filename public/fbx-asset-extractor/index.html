3D Asset Extractor

Extract mesh objects and texture assets from FBX, GLB, GLTF, OBJ, STL, PLY, DAE and 3DS models. Inspect what is inside a model, download each asset on its own, or grab the whole batch as a ZIP. Everything runs in your browser — the file is never uploaded.

What it extracts

Mesh objects

Each mesh in the model becomes its own file. Choose OBJ, GLB, STL or PLY; world transforms are baked into the exported geometry.

Embedded textures

Images embedded inside FBX, GLB/GLTF and DAE files are written out in their original format where possible (PNG, JPG, BMP, GIF, WebP, TGA and more) with previews where the browser can display them.

Materials and references

Material names and assigned map slots are listed. Texture paths that point to external files are reported, but never fetched.

Batch processing

Drop several 3D files at once. Each is processed independently, so one broken file does not stop the rest.

Split components with independent materials

Switch the tool to Split components to choose individual mesh objects from the model hierarchy. Each selected component is exported separately — not merged — with its own material definitions, even when several components shared one material in the source file.

  • Per-face material slots, UVs and normals are preserved for every component.
  • Shared materials are duplicated per component, so editing one never changes another.
  • Texture references are kept; shared textures are copied unchanged into each package.
  • OBJ output ships an MTL file plus a textures/ folder; GLB embeds materials and textures.
  • With several source files, each file gets its own folder in the ZIP.

OBJ + MTL imports natively in Unity and keeps the objects separate with their own materials. GLB keeps full PBR maps, including tangents, but requires a glTF importer in Unity. Skinning, morph targets and animation are not included in component packages.

How it works

Geometry is read with the matching three.js loader for each format. Embedded images keep their original bytes when the container exposes them (FBX, GLB and embedded glTF); images decoded by the loader are re-encoded as PNG. Progress is reported per stage — analyzing, extracting meshes, extracting textures — and each file shows its own status.

For multiple files, the ZIP is organised into one folder per source model, with meshes/, textures/ and a report.json describing what was extracted.

Good to know

  • Limit: 200 MB per file, up to 30 files per batch.
  • Supported inputs: FBX, GLB, GLTF, OBJ, STL, PLY, DAE and 3DS.
  • Only meshes and texture media stored inside the file can be extracted.
  • External texture paths cannot be read in the browser; they are listed for reference.
  • OBJ, STL and PLY are geometry-only. A single .gltf cannot read external .bin buffers; use a self-contained .glb or embedded glTF. DAE and 3DS usually reference external images.
  • ASCII FBX files usually reference textures externally rather than embedding them.
  • Meshes can be exported as OBJ, GLB, STL or PLY. Component packages export as OBJ + MTL or GLB; all output is static geometry without skinning or animation.
  • Very large models may take a few seconds to parse; the interface shows progress and stays on the tool.

Privacy

Files are read into page memory and processed locally. Nothing is stored on a server, and generated assets exist only until you leave or reset the page. See the Privacy Policy for details.
