FBX Asset Extractor

Extract mesh objects and texture assets from FBX 3D model files. Inspect what is inside a model, download each asset on its own, or grab the whole batch as a ZIP. Everything runs in your browser — the FBX is never uploaded.

What it extracts

Mesh objects

Each mesh in the FBX becomes its own file. Choose OBJ, GLB, STL or PLY; world transforms are baked into the exported geometry.

Embedded textures

Images stored inside the FBX container are written out in their original format (PNG, JPG, BMP, GIF, WebP, TGA and more) with previews where the browser can display them.

Materials and references

Material names and assigned map slots are listed. Texture paths that point to external files are reported, but never fetched.

Batch processing

Drop several FBX files at once. Each is processed independently, so one broken file does not stop the rest.

Split components with independent materials

Switch the tool to Split components to choose individual mesh objects from the FBX hierarchy. Each selected component is exported separately — not merged — with its own material definitions, even when several components shared one material in the source file.

  • Per-face material slots, UVs and normals are preserved for every component.
  • Shared materials are duplicated per component, so editing one never changes another.
  • Texture references are kept; shared textures are copied unchanged into each package.
  • OBJ output ships an MTL file plus a textures/ folder; GLB embeds materials and textures.
  • With several source FBX files, each file gets its own folder in the ZIP.

OBJ + MTL imports natively in Unity and keeps the objects separate with their own materials. GLB keeps full PBR maps, including tangents, but requires a glTF importer in Unity. Skinning, morph targets and animation are not included in component packages.

How it works

Geometry is read with the three.js FBX loader. Embedded textures are decoded from the FBX container itself, so the original image bytes are preserved. Progress is reported per stage — analyzing, extracting meshes, extracting textures — and each file shows its own status.

For multiple files, the ZIP is organised into one folder per source FBX, with meshes/, textures/ and a report.json describing what was extracted.

Good to know

  • Limit: 200 MB per file, up to 30 files per batch.
  • Only the mesh objects and texture media stored in the file can be extracted.
  • External texture paths cannot be read in the browser; they are listed for reference.
  • ASCII FBX files usually reference textures externally rather than embedding them.
  • Meshes can be exported as OBJ, GLB, STL, PLY or ASCII FBX. FBX output is static geometry with basic materials — no skinning or animation.
  • Very large models may take a few seconds to parse; the interface shows progress and stays on the tool.

Privacy

Files are read into page memory and processed locally. Nothing is stored on a server, and generated assets exist only until you leave or reset the page. See the Privacy Policy for details.
